# Task 005 — Режим «Вивчення»: вибір тем і картки

**Файл у репозиторії:** `docs/tasks/005-learning-mode.md`

**Дата створення:** 03.11.2026  
**Проєкт:** English Cards — Laravel 13 / PHP 8.4 / MySQL / Docker Compose (WSL2)  
**Тип:** full-stack / learning UI / topic selection / access control

## 1. Мета та очікуваний результат

Реалізувати повноцінний режим **«Вивчення»** для авторизованого користувача з активним навчальним профілем: вибір однієї або кількох доступних тем, формування підбірки унікальних карток, перегляд англійського слова й українського перекладу, зручна навігація, повторне проходження та озвучення англійського слова.

**Результат після всіх етапів:** користувач обирає теми, за бажанням вмикає фільтр «Потрібно повторити», натискає «Почати вивчення», бачить картку `EN + UK`, переходить між картками кнопками або свайпами, за потреби слухає вимову, завершує перегляд і може пройти підбірку ще раз в іншому порядку або повернутися до вибору тем. Інтерфейс придатний для телефона та поточних тем оформлення.

**Головне правило:** у режимі «Вивчення» **не записувати й не змінювати прогрес** (`word_progress`, `knowledge_level`), навіть під час переходів, повторного проходження чи озвучення. Алгоритм «Знаю» / «Не знаю» належить окремому режиму **«Перевірка»**.

## 2. Функціональні вимоги та межі

### 2.1. Доступ і вибір тем

- Режим призначений **для авторизованого користувача з підтвердженим email та дійсним активним навчальним профілем**. Використовувати чинний механізм session-based профілю з перевіркою належності поточному акаунту.
- Доступні теми: **системні** (`topics.user_id IS NULL`) та **приватні теми поточного акаунта** (`topics.user_id = auth()->id()`). Приватні теми доступні всім навчальним профілям цього акаунта, але не чужим користувачам.
- Можна вибрати **одну або кілька тем**. Показувати назву, `topics.level` і кількість слів; за потреби — зрозумілий поділ «Системні / Мої» та фільтр **за рівнем теми**. Не вводити `course`/`lesson` — таких сутностей для MVP немає.
- За замовчуванням підбірка охоплює **всі слова обраних тем**, незалежно від поточного рівня знання. Опційний перемикач **«Потрібно повторити»** залишає тільки слова з ефективним `knowledge_level` **0–2**. Відсутній запис у `word_progress` означає рівень `0`; рівень `3` у цьому фільтрі не показується.
- Якщо одна картка входить до кількох обраних тем, **показувати її один раз** (`words.id`), без дублювання. Однаковий англійський запис із різними українськими перекладами — це **різні картки**, якщо `words.id` різний.
- Не починати перегляд без обраної доступної теми. Показувати зрозумілий стан, якщо доступних тем немає, теми порожні або за фільтром немає карток; запропонувати змінити вибір чи вимкнути фільтр.
- Валідація доступу **на сервері**: підмінені/чужі/видалені `topic_id`, підроблений `learning_profile_id` та прямий запит до маршруту карток не повинні дозволяти доступ до чужих приватних тем або профілів. Не довіряти самій видимості елементів у UI.
- Максимально **повторно використовувати** сторінки/компоненти тем із Task 004. Не створювати другий незалежний механізм авторизації чи другий довідник тем.

### 2.2. Картка та керування

- На картці **одразу** відображати `word_en` і `word_uk`. **Не потрібні** натискання для відкриття перекладу, ані кнопки «Знаю» / «Не знаю».
- Одна картка — в центрі уваги. Показати лічильник **«1 / N»** і зрозумілий контекст вибраних тем. Якщо тем кілька, не приписувати спільну картку лише одній довільній темі.
- Кнопки **«Назад»** і **«Далі»** для переходу між картками обов'язкові; вони мають бути зручними на сенсорному екрані. На першій картці «Назад» неактивна; на останній — зрозумілий перехід до завершення перегляду.
- Додатково підтримати горизонтальні свайпи: **ліворуч — наступна**, **праворуч — попередня**. Свайпи не повинні заважати вертикальному прокручуванню сторінки; кнопки залишаються основним доступним способом керування. За можливості — клавіші `←` / `→`, без втручання в поля вводу.
- Порядок карток **перемішується на початку проходження** і залишається стабільним протягом цього проходження (переходи «Назад»/«Далі» не змінюють порядок). **«Пройти ще раз»** запускає нове проходження тієї самої підбірки з новим перемішуванням. Не вимагати гарантовано іншого порядку для набору з однієї-двох карток.
- Після останньої картки показати простий екран завершення: кількість переглянутих карток, **«Пройти ще раз»**, **«Змінити теми»**. **Не** видавати перегляд за результат перевірки знань і не показувати вигадані показники прогресу.
- Під час перезавантаження сторінки допустимо **почати поточне проходження заново**. Не створювати БД-таблицю сесій перегляду, фонові записи чи обов'язкове відновлення позиції. Вихід із режиму має бути зрозумілим.

### 2.3. Вимова й оформлення

- Додати **кнопку озвучення англійського слова** у нижній зручній для пальця частині картки; виклик тільки за дією користувача, без автозапуску звуку.
- Для MVP застосувати **браузерний Web Speech API (`speechSynthesis`)**, за доступності; мова англійська (`en-*`). Не завантажувати та не зберігати аудіофайли, не підключати зовнішні платні TTS/API.
- Якщо TTS у браузері недоступний або відтворення не вдалося, показати ненав'язливе повідомлення; **перегляд карток повинен працювати незалежно від аудіо**. Не припускати наявність певного голосу на кожному пристрої.
- У режимі «Вивчення» **не показувати постійне громіздке меню сайту**: залишити компактний верхній елемент навігації (наприклад, `☰`) для виходу/переходу до інших розділів. Не прибирати можливість повернутися чи змінити профіль.
- **Поки без зображень та прикладів речень**, навіть якщо в моделі передбачені необов'язкові поля. Не додавати порожні блоки-заглушки, випадкові ілюстрації чи генерацію зображень.
- Використовувати чинні `system` / `light` / `dark` та адаптивний mobile-first UI. Не проводити глобальний редизайн застосунку в межах цього task.

### 2.4. Що не входить

- Режим «Перевірка», «Показати переклад», кнопки «Знаю» / «Не знаю», друге коло незнаних слів, підвищення/скидання рівня, пакетне збереження результатів та IndexedDB.
- Гостьовий/деморежим без авторизації: це **окрема майбутня задача**; у цьому task не відкривати приватні теми гостям.
- Створення/редагування/видалення тем і слів, CSV-імпорт, додаткові фільтри складності, обмеження кількості карток, статистика, streak, гейміфікація й PWA/offline.
- Нові таблиці або поля, черги, scheduler, зміна Docker, Composer/npm-залежностей, зовнішні TTS-сервіси, деплой.
