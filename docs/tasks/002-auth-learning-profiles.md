## 1. Мета та очікуваний результат

Реалізувати робочий базовий сценарій: відвідувач реєструється за email і паролем, підтверджує email, входить у застосунок, створює або вибирає навчальний профіль, редагує його назву й налаштування оформлення, перемикається між своїми профілями та виходить із системи. Передбачити відновлення забутого пароля. Інтерфейс має бути mobile-first і візуально узгодженим з ескізами English Cards.

**Результат після всіх етапів:** авторизація й керування профілями працюють наскрізно через браузер; ізоляція даних між акаунтами перевірена; теми `system` / `light` / `dark` коректно застосовуються; автоматизовані тести проходять в ізольованій MySQL-БД. **Екрани навчання, перевірки, словник та імпорт не реалізовувати в цьому task.**

## 2. Узгоджені рішення та обсяг

### Узгоджено власником проєкту

- Авторизація через **email + пароль**; **без Google OAuth** у цьому task.
- Реєстрація, вхід, вихід, відновлення пароля й **верифікація email**.
- Один акаунт може мати **кілька навчальних профілів**; `learning_profiles.user_id` — власник, `learning_profiles.name` — назва профілю.
- Оформлення належить **навчальному профілю**: `learning_profiles.theme_preference` = `system` / `light` / `dark`, за замовчуванням `system`.
- Світлий і темний ескізи — візуальний орієнтир для всіх нових сторінок, включно з auth/profile UI; адаптивність **mobile-first**.
- Усі PHP/Composer/Node-команди виконувати в контейнерах, без інсталяції інструментів у WSL Ubuntu. **Не змінювати Docker/залежності без попереднього погодження.**
- База з Task 001 уже мігрована локально, коміти зроблені; **не повторювати руйнівну ініціалізацію**.
- Для локального тестування email verification та password reset погоджено окремий Docker Compose-сервіс **Mailpit** без реального надсилання листів назовні; реалізація — на Етапі 2.

### Потрібно вирішити на Етапі 1, до встановлення пакетів і реалізації UI

- Frontend-стек: оцінити найпростіший підтримуваний варіант для Laravel 13, майбутніх мобільних карток/свайпів і цього проєкту; **запропонувати** (наприклад, Blade + Alpine або інший обґрунтований варіант), описати наслідки та отримати згоду власника. **Не обирати й не встановлювати самовільно.**
- Спосіб збирання frontend у Docker (якщо потрібні Node/Vite/npm): у чинному Compose немає гарантованого Node-сервісу. Запропонувати мінімальне рішення без установлення Node у WSL та отримати погодження.
- Спосіб реалізації auth (вбудовані можливості Laravel / starter kit / власні контролери) — запропонувати з поясненням залежностей. Не додавати важкий стек без необхідності.
- Правила активного профілю: запропонувати **серверне session-based** збереження `active_learning_profile_id` з перевіркою належності при кожному читанні; без нової колонки в БД, якщо немає обґрунтованої потреби. Узгодити перш ніж реалізовувати.
- Поведінка після реєстрації, до/після email verification, за відсутності профілів, а також потреба в автоматичному першому профілі. За замовчуванням **не створювати профіль приховано**: пропонувати явне створення, якщо чинна бізнес-логіка не вимагає іншого.
- Локальна доставка тестових email (перевірити наявні сервіси; запропонувати log mailer або локальний catcher без реальної відправки назовні).

### Входить

- HTTP routes, контролери/requests/сервіси, політики або інші перевірки авторизації, браузерні сторінки та повідомлення про помилки.
- Реєстрація, login/logout, email verification із повторним надсиланням листа, forgot/reset password.
- Створення, перегляд списку, вибір активного профілю, редагування назви та вибір теми профілю; всі операції доступні лише власнику.
- Мінімальна стартова сторінка для авторизованого користувача після вибору профілю (без фальшивих карток/метрик).
- Спільні компоненти UI, три режими оформлення, адаптивна верстка, базова доступність.
- Автоматизовані feature-тести auth/profile/security та перевірка інтерфейсу доступними засобами.

### Не входить

- Google OAuth, соціальні логіни, 2FA, адмінпанель, ролі, публічні профілі.
- CRUD тем/слів, CSV-імпорт, навчальні сесії, алгоритм «Знаю» / «Не знаю», синхронізація прогресу, IndexedDB та PWA/offline.
- Реалізація самих екранів карток із ескізів, реальний Dashboard із прогресом, підрахунок статистики.
- Видалення навчального профілю й каскадне видалення навчальних даних **без окремого погодження**; у цьому task достатньо створення, списку, вибору та перейменування.
- Production email-провайдер, production деплой або налаштування DNS.
