# Task 007 — Збереження прогресу

**Проєкт:** English Cards  
**Статус:** Заплановано  
**Залежність:** Task 006 — режим «Перевірка»

## 1. Мета

Реалізувати надійне збереження результатів перевірки слів для кожного навчального профілю.

Після проходження перевірки користувач повинен отримувати оновлені рівні знання слів. Результати не повинні губитися через тимчасову втрату інтернету або повторно застосовуватися через дублювання запитів.

Використати наявні таблиці:

- `word_progress`
- `progress_sync_batches`

Не створювати нових таблиць без обґрунтованої необхідності та попереднього погодження.

## 2. Правила бізнес-логіки

### Рівні знання

| Рівень | Значення |
|---|---|
| 0 | Нове або незнайоме слово |
| 1 | Один раз підтверджено «Знаю» |
| 2 | Двічі підтверджено «Знаю» |
| 3 | Тричі підтверджено «Знаю», умовно засвоєне |

Правила зміни прогресу:

- «Знаю» у першому колі → збільшити рівень на 1, максимум до 3.
- «Не знаю» у першому колі → скинути рівень до 0.
- «Знаю» або «Не знаю» під час повторного кола → рівень залишається 0.
- Одне слово може отримати максимум одне підвищення за сесію.
- Відсутній запис у `word_progress` означає рівень 0.
- Перегляд карток у режимі «Навчання» не змінює прогрес.
- Повторне проходження перевірки створює нову сесію.
- Рівень знання одного слова спільний між темами в межах одного навчального профілю.
- Різні навчальні профілі мають незалежний прогрес.

### Збереження відповідей

- Після кожної відповіді зберігати стан перевірки локально в IndexedDB.
- Після завершення перевірки надсилати відповіді одним пакетом до Laravel.
- Сервер самостійно розраховує нові рівні знання.
- Не довіряти готовим значенням `knowledge_level` із браузера.
- Повторне надсилання того самого пакета не повинно повторно змінювати прогрес.
- Не видаляти локальний пакет, доки сервер не підтвердив його успішну обробку.

### Перервані перевірки

Якщо користувач закрив браузер під час перевірки:

- Зберегти вже надані відповіді.
- Під час наступного відкриття застосунку виявити незавершену сесію.
- Закрити її як перервану та синхронізувати надані відповіді.
- Не вважати картки без відповідей такими, що отримали «Не знаю».
- Нову перевірку починати з новим UUID.

### Історія

Повну історію проходжень у MVP не зберігати.

`progress_sync_batches` використовувати для захисту від повторного застосування пакетів і збереження короткого результату синхронізації.

Розширена історія, статистика за датами та графіки — поза межами Task 007.

- Обмеження: поточна браузерна перевірка використовувала синтетичну сторінку та підтвердження замість повного авторизованого Laravel/UI-сценарію; Firefox, Safari, фізичні пристрої й міжпристроєвий порядок не перевірялися. Результати наскрізної перевірки Task 006 наведені в його нотатках. Недоліків, що потребують змін коду, не виявлено; змінено лише цей task-файл.
