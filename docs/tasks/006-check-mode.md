# Task 006 — Режим «Перевірка» для English Cards

**Файл у репозиторії:** `docs/tasks/006-check-mode.md`  
**Статус:** Етапи 1–2 не завершено: браузерні перевірки відкриті; Етапи 3–4 не розпочато
**Дата створення:** 03.11.2026  
**Проєкт:** English Cards — Laravel 13 / PHP 8.4 / MySQL / Docker Compose (WSL2)  
**Тип:** full-stack / checking / progress / UI

## 1. Мета та очікуваний результат

Реалізувати режим **«Перевірка»**: користувач обирає теми так само, як у режимі **«Навчання»** (Task 005), бачить англійську картку, за потреби відкриває переклад і оцінює себе кнопками **«Знаю» / «Не знаю»**. Слова, на які в першому колі відповів «Не знаю», один раз з'являються у другому колі. Після проходження користувач бачить результат; відповіді надійно передаються в Laravel, який оновлює прогрес **активного на момент початку перевірки навчального профілю**.

**Головний UI-принцип:** «Перевірка» — не окрема дизайн-система. **Використати фактичний поточний вигляд, структуру, компоненти та поведінку «Навчання» з Task 005**, зокрема вже погоджені пізніші UI-правки. Відмінності — тільки ті, які потрібні перевірці.

**Результат після всіх етапів:** працює повний шлях **вибір тем → перевірка → друге коло (за потреби) → синхронізація → результати**, а помилки мережі, повторні HTTP-запити та перервані сесії не призводять до повторного або чужого нарахування прогресу.

## 4. Правила інтерфейсу та алгоритму (для всіх етапів)

### 4.1. Вибір тем — як у «Навчанні»

- Вхід із головної сторінки через дію **«Перевірка»**. Обов'язкові авторизація, підтверджений email та власний активний навчальний профіль — за правилами Task 005.
- **Повторно використати спільний механізм і UI вибору тем** Task 005, а не створювати копію, яка згодом розійдеться за дизайном. Однакові пошук, фільтри, чекбокси, лічильники, стани без даних, мобільне компонування та світла/темна тема.
- Зберегти погоджений сценарій **однієї сторінки з двома станами**: список для вибору тем → компактний огляд вибраних тем. **«Змінити теми»** повертає список зі збереженим вибором; **«Скинути фільтри»** не очищає вибрані теми; **«Очистити вибір»** знімає всі галочки.
- Список доступних тем: системні + приватні **поточного користувача**; чужі приватні теми заборонені. Не міняти загальні правила видимості Task 005. Теми без слів можуть відображатися, але не повинні створювати порожню перевірку.
- Для набору використовувати ті самі параметри, які підтримує актуальне «Навчання»: декілька тем, **«Усі слова»** за замовчуванням або **«Потрібно повторити»** (`knowledge_level` `0–2`), наявне обмеження кількості карток (якщо реалізовано). Однакове слово в декількох вибраних темах потрапляє в набір **один раз за `word_id`**.
- Кількість доступних карток і порожній результат рахувати **для сформованої унікальної підбірки**, а не як суму слів тем. Не відкривати перевірку з нульовою кількістю карток.

### 4.2. Картки — як у «Навчанні», але з відкриттям відповіді

- Зберегти **той самий каркас сторінки і картки**, відступи, типографіку, індикатор прогресу, контекст обраних тем, верхнє компактне меню **☰** та mobile-first компонування. Не повертати постійне нижнє навігаційне меню. Врахувати фактичний стиль Task 005; не копіювати застарілий макет буквально.
- Спочатку видно **лише `word_en`**. `word_uk` прихований до натискання **«Показати переклад»**. Наразі без зображень, частин мови чи необов'язкових речень.
- Кнопки **«Знаю» / «Не знаю»** доступні одразу, незалежно від відкриття перекладу. Показ перекладу й прослуховування не змінюють прогрес і не перемикають картку.
- Обидві кнопки мають **текст без стрілок**; натискання фіксує оцінку та **автоматично переходить на наступну картку**. Не трактувати «Знаю»/«Не знаю» як «Далі»/«Назад».
- На відміну від «Навчання», **не додавати «Назад»/«Далі» для вже оцінених карток**: одна відповідь на картку в межах кола, без тихого переписування попередньої. Для дострокового завершення — кнопка поруч із номером кола, підтвердження та обробка перерваної сесії.
- Якщо свайпи реалізовані, вони означають **саме оцінку**, а не навігацію, і доступні незалежно від відкриття перекладу. Кнопки завжди доступні як основний спосіб керування. Не конфліктувати з прокручуванням сторінки та браузерними жестами.
- Використати наявну озвучку слова з Task 005 (якщо вона вже реалізована), без нового аудіомеханізму. Підтримати керування з клавіатури, видимий focus і достатні зони натискання.

### 4.3. Два кола й прогрес

- Перше коло: **один раз перемішати** унікальну підбірку на старті перевірки. Зберігати порядок і вже дані відповіді протягом цієї сесії.
- «Не знаю» в першому колі додає картку в повторення. Друге коло починається **після всього першого** й містить лише ці картки, **один раз у новому перемішаному порядку**. Якщо таких немає — відразу результати. **Третього автоматичного кола немає**.
- `knowledge_level` прив'язаний до **`learning_profile_id + word_id`**; відсутній запис = рівень `0`. «Знаю» у **першому колі** збільшує рівень на `1` (максимум `3`, не частіше одного разу за сесію); «Не знаю» скидає до `0`. Якщо в першому колі було «Не знаю», **будь-яка** відповідь у другому колі залишає рівень `0`.
- Зміни прогресу остаточно обчислює **сервер**, а не frontend. Не створювати записів прогресу під час простого перегляду «Навчання».

### 4.4. Збереження та завершення

- **Після кожної відповіді** зберігати її та необхідний стан поточної перевірки **в IndexedDB до переходу далі**; не надсилати HTTP-запит для кожної картки.
- Після завершення або переривання формувати один **незмінний пакет** відповідей з `session_uuid`, власником, профілем і відповідями; передавати в Laravel. Пакет не видаляти з IndexedDB до підтвердження сервера.
- Повторний той самий UUID + той самий пакет — **ідемпотентний**; той самий UUID + інший вміст — конфлікт. Не застосовувати пакет до чужого профілю або до профілю, що став активним пізніше.
- Якщо сторінку закрито до завершення, під час наступного входу **закрити попередню перевірку як перервану**, надіслати **тільки вже зроблені відповіді**, а нову починати з новим UUID. Не вважати картки без відповіді «Не знаю».
- Не оголошувати прогрес синхронізованим до підтвердження сервера. Якщо синхронізація не вдалася — показати стан помилки, зберегти дані та запропонувати повторну спробу; не запускати нову перевірку цього профілю поверх невідправленого пакета без узгодженого порядку.
